# LAN Toolkit — локальная сеть Windows ⇄ Linux ⇄ Android + Minecraft

**Русский** · [English](README_EN.md) · [Deutsch](README_DE.md) · [Español](README_ES.md) · [中文](README_ZH.md)

Набор скриптов для связи компьютеров и телефона в одной локальной сети: общая папка (SMB),
сетевая видимость, SSH, обмен файлами через браузер, мобильный хот-спот и Minecraft-сервер
(Java и Bedrock).

> Ввод команд не требуется: файлы запускаются двойным кликом, все действия выбираются
> цифрами в меню на русском языке.

---

## Быстрый старт

### Windows

1. Запустите `НАЧАТЬ-Windows.bat` (или `START-Windows.bat`) двойным кликом.
2. Подтвердите запрос контроля учётных записей («Разрешить этому приложению вносить изменения») — «Да».
3. В открывшемся меню выберите пункт **`1`** и нажмите Enter: сеть подготовлена.
   Пункты 4 и 5 в том же меню отвечают за Minecraft.

### Linux

1. Поместите файлы `start-linux.sh`, `lan-linux.sh` и `НАЧАТЬ-Linux.desktop` в один каталог.
2. Запустите `НАЧАТЬ-Linux.desktop` двойным кликом; при запросе разрешите выполнение файла.
3. Введите пароль администратора и выберите пункт **`1`** в меню.

Если двойной клик не срабатывает: откройте каталог в терминале и выполните `bash start-linux.sh`.

### Android (Termux)

1. Установите Termux из **F-Droid**: версия из Play Market устарела.
2. Скопируйте каталог `lan-toolkit` на устройство (или загрузите его через браузер).
3. В Termux выполните один раз:

   ```
   cd ~/storage/downloads/lan-toolkit && bash lan-android.sh
   ```

   Дальше — выбор пунктов меню.

> Прямое монтирование папки Windows на Android без root невозможно. Для доступа к файлам
> по SMB используется сторонний файловый менеджер, например Cx File Explorer
> (Сеть → Новое подключение → SMB, адрес `smb://<IP_ПК>/LAN`). Остальные возможности
> доступны через SSH и браузер — они есть в меню.

## Обновление

Текущая версия отображается в заголовке меню. Если в репозитории опубликована более новая,
меню выводит `>>> ДОСТУПНО ОБНОВЛЕНИЕ <<<`, а обновление запускается пунктом **16** (Windows),
**17** (Linux) или **14** (Android). Из командной строки:

```powershell
.\lan-win.ps1 update-check     # только проверить
.\lan-win.ps1 update           # скачать, проверить и установить
.\lan-win.ps1 rollback         # вернуть предыдущую версию из бэкапа
.\lan-win.ps1 no-update        # отключить проверку при запуске меню
```
```bash
sudo bash lan-linux.sh update-check
sudo bash lan-linux.sh update
sudo bash lan-linux.sh rollback
```

Порядок действий при обновлении — **ни одна замена не выполняется, пока новое не проверено**:

1. Запрашивается версия из файла `VERSION` в репозитории.
2. Через API GitHub определяется **точный коммит ветки `main`**, файлы загружаются по нему.
   Так кэш CDN не может отдать набор файлов на более старом коммите (такой случай наблюдался).
3. Загружается `MANIFEST.txt`, сверяется **sha256 каждого файла** (суммы считаются
   без учёта переводов строк, поэтому Windows и Linux дают одинаковый результат).
4. Проверяется синтаксис новых скриптов: `ParseFile` для PowerShell, `bash -n` для `.sh`.
5. Текущие файлы копируются в `~/.lan-toolkit/backup/<версия>-<дата>/`.
   **Бэкап обязателен:** если копию создать не удалось, обновление отменяется.
6. Только после этого файлы заменяются. Любая ошибка на шагах 1–4 → отмена, состояние не меняется.

В Windows файлы загружаются поимённо, без распаковки архива: `tar.exe` декодирует кириллические
имена (`НАЧАТЬ-Windows.bat`) как CP866 и создаёт нечитаемые имена. В Linux и Android
используется архив ветки — там `tar` читает имена корректно.

**Границы защиты.** Файлы и контрольные суммы берутся из одного источника (GitHub по HTTPS),
поэтому это защита от обрыва связи, повреждения файла и ошибок в скриптах, но не от подмены
сервера. Для полной гарантии используется установка из git с проверкой коммитов.

Примечания:

* Проверка обновлений при запуске меню занимает около 3 секунд и не мешает работе;
  без доступа к сети она просто ничего не выводит. Отключение: `no-update` или `NOUPDATECHECK=1`.
* После обновления обновите и вторую машину: в режиме «партнёр» хеши тулкитов должны совпадать,
  иначе вторая сторона откажет.
* `update-manifest` пересобирает `MANIFEST.txt` — выполняется после правок скриптов,
  иначе обновление у других машин упрётся в несовпадение сумм.

## Minecraft в этой же сети

Java и Bedrock — **разные миры**: без плагинов Geyser + Floodgate они друг друга не видят.

**Вариант без сервера (хост — Windows).** В игре: `Esc` → «Открыть для сети». Остальные
участники подключаются по IP хоста. Ограничение: хост должен оставаться в игре.

**Полноценный сервер:**

| Сторона | Действие |
|---|---|
| Windows | меню → пункт **4** (запрашивает объём памяти в ГБ). Файл `server.jar` помещается в `%PUBLIC%\LANShare\minecraft` |
| Linux | меню → пункт **4** (Java/Paper, загружается автоматически) или **5** (Bedrock-сервер) |
| Android | меню → пункт **6** (сервер на телефоне, для 1–2 человек; предварительно `termux-wake-lock`) |

| Версия игры | Куда вводить адрес |
|---|---|
| Java Edition | Multiplayer → Direct Connection → `<IP>:25565` |
| Bedrock (телефон, Win-Store, консоль) | Play → Servers → Add Server → `<IP>:19132` |

Особенности:

- Порт 25565 требуется **и по TCP, и по UDP**.
- Bedrock всегда **UDP 19132**; автопоиск LAN на телефоне ПК не видит, адрес вводится вручную.
- Без `eula=true` в `eula.txt` сервер завершается с ошибкой (скрипты создают файл сами).
- Кросс-плей: на Paper-сервер помещаются `Geyser-Spigot.jar` и `Floodgate.jar` в `plugins/`.
- Телефон-сервер: без `termux-wake-lock` Termux засыпает и сервер отключается.

## Поиск запущенной игры («Открыть для сети»)

Речь не о сервере, а об обычной игровой сессии: скрипт находит java-процесс клиента и его
слушающий порт, после чего выполняет настоящий Minecraft-пинг — так определяются мир, версия
и список игроков.

```powershell
.\lan-win.ps1 detect
```

Пример вывода (значения обезличены):

```
  Найдено: КЛИЕНТ (игра)  PID 10000
    Инстанс : <название сборки> (MultiMC)
    Версия  : 1.20.1
    ЛОКАЛЬНАЯ СЕТЬ ОТКРЫТА -> порт 55534
      Мир      : player1 - <название мира>
      Версия   : 1.20.1 (protocol 763)
      Игроки   : 2/8
      Сейчас в игре: player1, player2
      Адрес для друзей:
        192.168.1.20:55534
```

Как это работает: используется пинг протокола Server List Ping (`0x00` handshake → `0x00` status →
JSON с MOTD, версией и списком игроков), поэтому «порт открыт» и «это действительно Minecraft»
не путаются. Порт у «Открыть для сети» **случайный и меняется каждый раз**, вручную его
подбирать бессмысленно — `detect` извлекает его из процесса.

Аналоги:

- Linux: `sudo bash lan-linux.sh detect`
- Android (скан подсети + поиск LAN-игр): `bash lan-android.sh scan`
- Отдельная утилита: `python3 mcping.py ping <IP> <порт>` / `scan <192.168.1>` / `listen`

Примечание: мультикаст-объявления `224.0.2.60:4445` (по ним клиенты видят друг друга в меню
«Сетевая игра») часто блокируются брандмауэром Windows и Wi-Fi-роутерами. Прямое подключение
по `<IP>:<порт>` работает всегда, поэтому `detect` — основной способ, а не мультикаст.

## Перенос мира между машинами

Мир — это каталог с `level.dat` (а также `session.lock`, `region/`, `playerdata/`). Скрипты
синхронизируют его через общую папку в обе стороны, **по принципу «новее побеждает»**
и с автоматическим бэкапом перед каждым изменением.

```powershell
.\lan-win.ps1 world -WorldMode list                  # какие миры есть и где
.\lan-win.ps1 world -WorldMode push  -World "имя" -Remote \\192.168.1.50\LAN\mcworlds
.\lan-win.ps1 world -WorldMode pull  -World "имя" -Remote \\192.168.1.50\LAN\mcworlds
.\lan-win.ps1 world -WorldMode sync  -World "имя" -Remote \\192.168.1.50\LAN\mcworlds
```
```bash
sudo bash lan-linux.sh world list
sudo bash lan-linux.sh world sync "имя мира" /mnt/lan/mcworlds
```

Защиты:

- **Мир занят игрой → синхронизация запрещена.** `session.lock` проверяется эксклюзивным
  открытием, дополнительно проверяется наличие java-процесса клиента: копирование каталога,
  открытого игрой, гарантированно даёт повреждённый мир. Обход — только явный `-Force`
  (Windows) / `FORCE=1` (Linux).
- **Бэкап перед каждым прогоном**: `_backups/<мир>-<дата>.zip` (Windows) или `.tar.gz` (Linux).
- **Режим по умолчанию ничего не удаляет** (robocopy `/E /XO`, rsync `--update`): удаления
  не распространяются между машинами. Зеркалирование (`-Mirror` / `MIRROR=1`) существует,
  но удаляет файлы на обеих сторонах.
- Windows-скрипт находит миры всех лаунчеров: Prism, MultiMC, ванильный `.minecraft`,
  а также Bedrock-миры (UWP, `levelname.txt` читается как UTF-8).

## Двусторонний обмен папками

Постоянно работающая общая папка между двумя машинами: файлы доезжают в обе стороны.

```powershell
.\lan-win.ps1 sync -Local "$env:USERPROFILE\Desktop\обмен" -Remote \\192.168.1.50\LAN\обмен -Watch 30
```
```bash
sudo bash lan-linux.sh sync /home/user/обмен /mnt/lan/обмен 30
bash lan-android.sh sync ~/storage/shared/Download user@192.168.1.20:/home/user/обмен 30
```

`-Watch 30` — проход каждые 30 секунд (остановка — Ctrl+C); без числа выполняется один проход.
Логика без удалений; для полного зеркала добавляются `-Mirror` (Windows) или `MIRROR=1`.

## Режим «партнёр»: удалённое подключение к второй машине

Режим удалённой синхронизации: **инициатор подключается ко второй машине по SSH и передаёт
ей запрос на выполнение её половины синхронизации.** На обеих машинах должен лежать один и тот
же тулкит (проверяется по хешу).

Схема работы: инициатор по SSH запускает на второй машине `peer-serve`, передаёт запрос в stdin,
а вторая сторона **сама решает, принимать ли его**, и выполняет работу своими средствами —
свою шару, свой `robocopy`/`rsync`.

### Настройка (4 шага)

```powershell
# 1) на ОБЕИХ машинах установить тулкит, у себя создать ключ
.\lan-win.ps1 peer-keygen

# 2) указать партнёра и залить к нему скрипты
.\lan-win.ps1 peer-add -Peer pc2 -PeerHost 192.168.1.50 -PeerUser user -PeerPlatform win
.\lan-win.ps1 peer-bootstrap -Peer pc2

# 3) добавить свой публичный ключ на вторую машину (см. вывод peer-keygen)
#    Windows: C:\Users\<user>\.ssh\authorized_keys
#    Linux/Android: ssh-copy-id -i ~/.lan-toolkit/keys/id_ed25519.pub user@IP

# 4) НА ВТОРОЙ МАШИНЕ вручную взвести приём:
#    bash lan-linux.sh peer-arm -t мойКод123 -m 30
```

Проверка: `.\lan-win.ps1 peer-test -Peer pc2`
Синхронизация: `.\lan-win.ps1 peer-sync -Peer pc2 -Local "$env:USERPROFILE\Desktop\обмен" -RemoteDir /srv/lanshare/обмен -Watch 30`

Без шага 4 (взведения) вторая машина **откажет** — это основной механизм защиты.
Взвести приём удалённо нельзя: команды `peer-arm`/`peer-disarm` не входят в белый список.

### Механизмы защиты

| Защита | Как работает |
|---|---|
| SSH-доступ | Требуется уже разрешённый вход по ключу. Ключ тулкита добавляет человек на той машине. |
| Взведение вручную | Пока на второй машине не выполнен `peer-arm`, любой запрос получает `denied`. |
| Токен | Сравнивается SHA-256; в открытом виде нигде не хранится. Минимум 6 символов. |
| Срок | Максимум 240 минут, затем приём автоматически закрывается. |
| Одноразовость | `--once` — взведение сгорает после первого же запроса (гасится **до** работы, чтобы обрыв связи не оставлял доступ). |
| Привязка к инициатору | `--fp "user@ПК"` — принимать только с одной конкретной машины. |
| Белый список | Разрешены только `ping, hash, status, detect, world, sync`. Произвольный код запрещён. |
| Сверка скриптов | Хеш тулкита должен совпадать на обеих машинах. Иначе отказ (обход: `-AllowVersionDrift` / `ALLOW_DRIFT=1`). |
| Журнал | `~/.lan-toolkit/audit.log` — и удачные запросы, и отказы с причиной. |
| Отзыв | `peer-disarm` закрывает приём немедленно; `peer-forget` удаляет партнёра. |

Состояние (ключи, список партнёров, взведение, журнал) хранится **вне** тулкита —
в `~/.lan-toolkit`, поэтому не попадает ни в git, ни в копии папки обмена.

### Ограничения режима

- Не взводит вторую машину самостоятельно и не запрашивает пароль — используется только уже
  разрешённый SSH-доступ.
- Не выполняет произвольные команды — только действия из белого списка.
- Не прописывается в автозапуск и не держит постоянный канал: одно SSH-подключение на запрос.
- Не хранит пароли: только SSH-ключ тулкита.

### Примеры для Linux и Android

```bash
sudo bash lan-linux.sh peer-keygen
sudo bash lan-linux.sh peer-add pc2 192.168.1.50 user 22 win
sudo bash lan-linux.sh peer-bootstrap pc2
sudo bash lan-linux.sh peer-arm -t мойКод123 -m 30        # приём на этой машине
sudo bash lan-linux.sh peer-test pc2
sudo bash lan-linux.sh peer-sync pc2 /srv/lanshare/обмен /srv/lanshare/обмен 30
bash lan-android.sh peer-arm -t мойКод123 -m 30           # телефон как цель
bash lan-android.sh peer-sync pc  ~/storage/shared/lan  ~/lan
```

Отдельная утилита (одна команда, без скриптов):

```bash
python3 mcping.py ping 192.168.1.20 55534     # что за сервер на порту
python3 mcping.py scan 192.168.1              # кто в сети на 25565

python3 mcping.py bedrock 192.168.1.20        # Bedrock-сервер (UDP 19132)
```

| `-World` | все | самый свежий мир |
| `-Watch` / `sync ... <сек>` | все | `0` (один проход) |
| `-Mirror` / `MIRROR=1` | все | выключено (режим с удалением файлов) |

## Диагностика

1. **Нет пинга** → разные подсети (`ipconfig` / `ip a`). Если Wi-Fi гостевой, устройства
   изолированы: включите хот-спот (меню Windows, пункт 6) и подключите остальных к нему.
2. **Пинг есть, шара не видна** → брандмауэр: пункт 1 меню Windows открывает нужные правила.
3. **Запрашивается пароль** → нужна реальная учётная запись Windows (пустой пароль по сети
   запрещён политикой).
4. **Windows не видит Linux** → на Linux должны быть запущены `smbd`, `nmbd`, `avahi-daemon`
   (пункт 2 меню Linux).
5. **Android не открывает `smb://`** → Cx File Explorer / Material Files; либо файлы через
   браузер (`http` на ПК + `get` на телефоне).
6. **Windows 11 24H2 требует SMB-подпись** → на Linux-клиенте `vers=3.0` (уже в скрипте).

## Безопасность

- Шара доступна всей локальной сети; не рекомендуется использовать в публичных Wi-Fi.
- `remove` (пункт 8/9 в меню) откатывает внесённые изменения.
- Пароль SMB на Linux генерируется случайно и выводится один раз — сохраните его.
